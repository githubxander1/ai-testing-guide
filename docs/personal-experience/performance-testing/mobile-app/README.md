# 移动端性能与卡顿

本地资料覆盖启动时间、内存、CPU、FPS 和 Jank。整理时重点保留可复用的方法：固定场景、稳定设备状态、观察帧时间和资源变化；旧文档里的设备上限、工具阈值和计算公式不应直接视为当前通用标准。

## 按场景测

- 启动：区分冷启动、热启动，记录起止定义、设备状态和多次测量分布。
- 页面与滚动：覆盖常用列表、动画、图片加载和页面切换，记录卡顿出现的位置。
- 长时运行：在代表性操作下观察内存、CPU、温度、耗电和资源是否持续增长。
- 后台与恢复：检查切后台、返回前台、锁屏/解锁和网络切换后的性能及状态恢复。

## FPS 与帧时间

FPS 是一段时间内的刷新速率概览；均值可能掩盖少数很慢的帧。结合帧时间分布、卡顿发生位置和用户实际感受判断流畅度，并记录设备刷新率、系统版本、场景和采集工具。

Jank 的判断口径会受平台、工具和刷新率影响。对比版本时固定设备、场景、操作节奏和采集方式；问题定位时查看帧时间线以及主线程、渲染线程和 GPU 阶段，而不是只比较平均 FPS。

## 复现记录

记录设备型号、系统版本、屏幕刷新率、应用构建、温度/电量状态、网络、操作步骤、采集工具和原始结果。复测时尽量恢复相同条件，并保存问题时间点附近的性能跟踪。

Android 官方资料：[慢帧与卡顿排查](https://developer.android.com/topic/performance/issues/render)、[性能度量概览](https://developer.android.com/topic/performance/measuring-performance)、[JankStats](https://developer.android.com/topic/performance/jankstats)。工具的分类规则和阈值请按当前平台文档确认。

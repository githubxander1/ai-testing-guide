# 阿拉伯语 RTL 排版测试经验

阿拉伯语主要按从右向左（RTL）阅读。测试不能只看文字是否翻译正确，还要检查混排方向、布局、图标语义、截断、滚动和分享内容。本文整理当前项目经验；具体控件行为仍要以产品交互约定和设计稿为准。

## 一、文字方向与对齐

- 阿拉伯语正文按 RTL 阅读，段落通常右对齐；检查标题、表单、列表、弹窗和长文本是否一致。
- 阿语与英文、网址、邮箱、电话号码或数字混排时，整体阅读顺序仍应正确。LTR 片段应作为独立片段显示，避免标点、括号或数字跑到错误位置。
- 数字、邮箱、电话号码等内容保持自身字符顺序，不做字符镜像；按界面布局需要右对齐或单独设置 LTR 方向。
- 不要只凭一张全阿语截图判断混排效果，增加阿语与英文、数字、标点组合的实际文案。

## 二、布局与图标

RTL 页面应按从右向左的阅读路径安排导航、列表和操作位置。实现和验收优先关注左右语义是否正确，不要把整页图像直接做 `scaleX(-1)`；这种做法会连文字、数字和不应翻转的图标一起镜像。

| 元素 | 预期检查 |
|---|---|
| 页面布局 | 导航层级、内容起始边、抽屉和操作区符合 RTL 阅读顺序；文字不被边缘或滚动条遮挡 |
| 前进、后退和方向箭头 | 按产品对“前进/后退”的语义调整方向；检查图标、点击结果和焦点顺序一致 |
| 音量显示条 | 检查起点、填充方向、拖动方向与设计约定一致 |
| 普通进度条 | 按产品规则检查方向；本项目经验中需要适配 RTL |
| 视频、音频播放进度 | 保持媒体时间轴的既定语义，不因页面 RTL 误翻转；检查拖动和时间标签 |
| 搜索、飞行模式等通用图标 | 通常不镜像，确认图标含义未变 |
| 撤销、重做等方向性图标 | 根据操作语义检查是否镜像，不能只按图形朝向机械处理 |
| 时钟、倒计时 | 时间数值顺序保持正确；同时检查对齐、分隔符和倒计时变化 |

具体应用可能对轮播、滑动切页和音量控件有自己的交互约定，应以需求或设计稿为准，把约定补进验收用例。

## 三、项目中遇到的检查点

1. **校对阿语文案**：以翻译确认的 Google 文档或项目指定源稿为准。英语与阿语混排在部分文档工具中可能显示顺序混乱，遇到差异先核对源文案和浏览器实际渲染，不要把文档编辑器展示直接当作页面结果。
2. **Safari 文本截断**：检查超过行数限制时末尾省略号是否显示、方向是否正确；覆盖短标题、长句、标点结尾和阿英混排。
3. **滚动条遮挡**：RTL 下检查滚动条所在侧、固定栏和浮层是否盖住文字或按钮；页面滚到底部和长列表中都要验证。
4. **跨屏切换与滑动**：本项目提出的验收预期是切换方向符合阿语阅读路径（左右切换时从左向右）；需按页面类型、手势定义和设计稿确认，不能把它当作所有组件的通用规则。
5. **第三方分享文案**：验证动态拼接的阿语正文、英文名称、链接、标点和表情，在系统分享面板及目标平台中的顺序和完整性。
6. **翻译验收**：提测后邀请阿语翻译或母语人员验收断词、换行、语气和地道程度。测试人员无法单独判断语言质量时，记录待确认项并跟进结论。

## 四、建议覆盖的测试组合

- 全阿语、阿语加英文、阿语加数字、阿语加网址/邮箱/电话。
- 短文案、超过一行、超过最大行数、含括号/引号/标点的文本。
- 页面首屏、长页面、滚动到底、弹窗/侧栏、横向切页和第三方分享。
- Safari 与项目支持的其他浏览器；同时检查不同屏幕宽度和系统字体渲染。
- 键盘焦点顺序、读屏方向和控件操作结果与视觉方向是否一致。
